# 环境与发布准备

目前完成的是本地开发基础。测试和生产的服务器、数据库、GitHub Environment 与部署流水线尚未创建。

| 环境 | APP_ENV     | 服务位置               | 数据与密钥   |
| ---- | ----------- | ---------------------- | ------------ |
| 开发 | development | 本地电脑               | 本地配置     |
| 测试 | test        | 待选择托管平台或服务器 | 独立测试资源 |
| 生产 | production  | 待选择托管平台或服务器 | 独立生产资源 |

APP_ENV 仅标识业务环境，不会自动创建或隔离服务和数据库。NODE_ENV 用于 Node.js 依赖的运行模式；以后部署测试和生产服务时可以都设为 production，而 APP_ENV 分别设为 test 和 production。

当前 HOST 默认 127.0.0.1，仅供本地访问。部署到容器或托管服务时，根据平台要求设置 HOST（常见为 0.0.0.0）及 PORT。

## 下一步

1. 提交工程初始化分支并推送到 GitHub。
2. 创建 PR，等待 CI 实际通过后合并。
3. 确定托管平台或服务器，再创建测试、生产服务与各自配置。
4. 按账号方案配置 GitHub test 和 production 环境及部署凭据。
5. 添加测试环境部署，验证健康检查和环境标识。
6. 发布测试通过的同一构建版本到生产，并演练回滚。

现在的 CI 只执行安装、类型检查、代码检查、格式检查、测试和构建，不会部署服务。
